# ニコニコ通信解析・公開資料整備の作業計画

作成・更新：2026-09-20 JST。これは調査タスク一覧であり、未着手項目の動作保証ではない。

**Goal:** 複数動画のタグ・投稿者情報を少ない通信で正確に取得できる条件を調べ、他の開発者・AIが安全に再検証できる資料を公開用に整える。

**Architecture:** 調査1件ごとに、仮説→最小検証→匿名化証拠→finding→概要→公開用選択版の順で記録する。製品実装、ローカル証拠、公開用資料を分離し、各調査の結論を独立に評価できるようにする。

**Tech Stack:** 既存Markdown・JSON台帳、Python標準ライブラリによる必要最小限の診断、Git branch / PR。新しいサービスや管理ツールの導入を前提としない。

**Spec:** 利用者が示した調査・公開条件を、この文書の共通条件と[公開資料ガイド](PUBLICATION-GUIDE.md)へ整理した。既存成果は[100件境界報告](SNAPSHOT-BATCH-BOUNDARY-20260920.md)と[外部資料台帳](EXTERNAL-SOURCES.md)を起点にする。

**実行方式:** この会話の担当が一覧から1件ずつ進める。別のCodexタスクを一斉作成しない。通常の推奨はAstra中。2026-09-20に利用者が今回の作業をAstra高へ変更すると明示したため、この継続では高を使用可能。高を超える設定へ勝手に変更しない。推奨レベルは作業の難しさに基づく担当者の見立てで、モデル比較の実測値ではない。

## 共通条件

- ニコランNG本体の変更は別の開発作業。調査結果を見つけただけで組み込まない。
- 1回の主目的は1つ。開始時にGit・適用ルール・最新版・同じendpoint/parameterの既存検証を確認する。
- 一括返却、指定可能なID数、ページ上限、URL長、ライブラリ内の分割通信を区別する。
- tags/userIdが返ることと、現在の正しい値であることを区別する。hiddenを退会済みと断定しない。
- いいね全件取得は未解決。一般会員の取得範囲と制限を明示し、制限回避を目的とする検証はしない。
- 有効な認証・一時キー、生通信記録、不要な個人情報、ローカルPC固有のパスを外部AIや共有物へ送らない。
- 元リポジトリ・記事は公開URLと固定revisionを優先。作者の文書・コード確認と現在の実通信を分ける。
- 実通信は逐次・少数・再試行なしを基本とし、予期しない認証/過負荷/通信失敗では止める。HTTP失敗を機能不存在と一般化しない。
- 調査結果には失敗・制約・未確認も記録する。旧証拠を消さず、後続確認で訂正できる形にする。
- 公開は資料単位。既存の非公開リポジトリ全体の公開設定を自動変更しない。秘密情報検査済みと一般公開済みを区別する。
